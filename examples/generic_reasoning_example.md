# Generic Synthetic Reasoning Example

Status: `SYNTHETIC_METHOD_ONLY`

这是虚构的方法片段，故意不提供出生时间、真实命盘或现实经历，也不声称对应任何具体人物。

## Synthetic facts

- 当前问题：工作结构。
- Topic Anchor：Career structure。
- Primitive X：强调结果、兑现与清晰交付。
- Primitive Y：强调角色、秩序、承接与协调。
- Local modifier：存在反复校验和边界摩擦。
- Supporting structure：资源接口支持交付，但没有证据证明更高层控制权。

## Method walk-through

1. **Primitive**：X 与 Y 分别提供作用方式，不直接给职业标签。
2. **Composition**：先把两者理解为“在角色/流程约束中完成结果交付”的共同机制；不是把两段星曜文案拼接起来。
3. **Topic**：Career Anchor 决定它优先描述工作方式；资源接口只作 supporting structure，不能单独替代 Anchor。
4. **Claim**：更可观察的候选是“倾向在职责、流程和交付标准清楚的环境里承担结果”，而不是某个精确职业。
5. **Boundary**：不能推出职位高、性格温和或收入高。若现实长期完全不依赖职责分工、流程承接或可验收交付，本条应降级。

这个片段只展示推理链和禁止推论，不提供完整人生报告。

## Synthetic user-report style sample

以下只演示 Public v1 的呈现形态，是虚构文字，不对应任何命盘、人物或星曜判断：

### 你这个人怎么运转

遇到信息不完整的事情时，你更自然地先把关键条件理清，再决定下一步。这个习惯能减少仓促判断；用得太多时，也可能让你在条件尚未齐备时迟迟不愿启动。

### 你怎么工作、怎么创造价值

你更容易在目标和验收标准清楚的任务里，把分散信息整理成可交付的结果。比起只维护流程，你可能更在意事情最终是否落地。

### 你在亲密关系里怎么运转

稳定相处更依赖把期待说清楚，并及时确认彼此对安排的理解；问题长期留在暗示层面时，误会容易累积。

### 可选总结

你倾向先理清条件再行动，这让你交付时更稳，也可能拖慢启动。工作上更容易通过整理信息并完成明确交付体现价值；关系里则需要把期待及时说清。

总结中的判断都已出现在前三节，没有增加新结论。示例不是固定模板，也不是命理规则。
