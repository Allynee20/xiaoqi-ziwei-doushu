# Star in Palace Grammar

## 基本组合

```text
Star semantic function
× Palace semantic object / role
× Question context
→ Contextual expression candidate
```

1. 星曜提供“怎样作用”的语义功能，不提供现实结果。
2. 宫位提供“作用在谁/什么领域”的对象接口，不提供固定吉凶。
3. 问题确定当前主语、角色和要回答的子问题。
4. `COMPOSITE_FIRST`：同宫或其他稳定共同结构中的多颗主星，先用各自 Primitive 识别共同机制、职责分工与相互牵制，再进入宫位与 Topic；不得把单星文本直接相加。辅煞只修饰主结构。
5. 对宫、三方与会照补充外部场景、资源和条件；不与本宫同权累加。
6. 最终表达必须列出边界和替代表现，不从象意跳到职业、婚期、金额、疾病或事件结果。
7. 没有预编码组合时，证据和边界足够可标 `REASONER_SYNTHESIS_ALLOWED`；不足则标 `UNRESOLVED`，不得因此停止全部分析或发明传统规则。

## 示例锚点（非穷举词典）

- 武曲的“结果/数字/兑现”落财帛的“收入/结算/资源调度”：可形成重视结算、效率与价值交换的候选；不等于收入高或从事金融。
- 天府的“收纳/守成/资源安排”落田宅的“固定基础/储存/资产使用”：V3 已批准其为财富留存的“storage support structure”之一；仍不等于实际资产多、一定留得住钱或房产结果。
- 文昌/文曲落官禄、财帛或子女主题：优先检查说明、版本、合同、验收与交付；不等于名声、学历或回款已经成立。

## 禁止

不构建 14×12 固定断语表；不穷举双星组合；不把案例中的结果反推成通用 Star×Palace 规则。
