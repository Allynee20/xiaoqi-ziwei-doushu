# Transform Application Grammar

```text
Original star semantic
+ Transform process modifier
+ Palace object / source layer
→ Which dimension of the original semantic changes?
```

处理顺序：

1. 先写原星的核心功能。
2. 确认四化来源：生年、宫干、大限、流年；不得混层。
3. 化禄问资源/入口如何增加；化权问责任/推动/决策如何增强；化科问何处显化、专业化或进入审核；化忌问何处形成卡点、纠缠、成本或收束。
4. 四化仍作用于原星语义，不能脱离 `boundStar + transform + physicalPalace` 自由漂浮。
5. 同星多化或禄忌并见可形成多维、甚至冲突性表达；各维保留，不做正负抵消。
6. 只有旧资产存在明确组合时才使用特殊 Transform×Star 语义；否则采用原星语义加最小四化过程机制，或标 `UNRESOLVED/TRACE_ONLY`。

V3 唯一已迁入的狭窄财富锚点：武曲化禄在财帛宫、本宫、本地物理来源满足既有条件时，是“直接赚钱形成结构存在”的支持信号；它不回答金额、能力、留存、波动、路径、时点或结果。
