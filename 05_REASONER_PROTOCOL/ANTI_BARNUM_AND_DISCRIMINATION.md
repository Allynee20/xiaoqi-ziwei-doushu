# Anti-Barnum and Discriminative Reasoning Protocol

Status: `REQUIRED_DEFAULT_PROTOCOL`

This protocol changes claim construction and validation only. It adds no star, palace, transform, topic, or dynamic semantics.

## 1. Five-part claim contract

Every important claim must contain all five labeled parts:

1. `EVIDENCE`: the minimum traceable structural facts and their source/layer.
2. `REAL_WORLD_DIMENSION`: a concrete observable axis such as fixed salary vs project settlement, organization vs client, stable path vs route change, self-earned vs transferred asset.
3. `CONTRAST`: what a materially different structure would emphasize instead. Use an explicit structural alternative already supported by V4; do not use lookup answers.
4. `CANNOT_IMPLY`: the nearest attractive overclaim that the evidence does not establish.
5. `MISS_CONDITION`: observable circumstances that would downgrade or falsify the claim.

A sentence missing any part is a draft, not a key conclusion. “Sounds reasonable” is never evidence.

## 2. Discrimination gate

Before release, ask whether the key sentence can be moved to a structurally different chart with only a name change.

```text
SWAPPABLE key claim → BAD → NON_DISCRIMINATIVE → remove or rewrite
NON_SWAPPABLE because evidence/dimension/miss condition differ → GOOD
```

Shared conclusions are allowed only when they are genuinely supported by both charts, are labeled `SHARED_STRUCTURAL`, and are not counted as a differentiating hit.

## Similarity gate

```text
SIMILAR STRUCTURE MAY PRODUCE SIMILAR REPORTS
```

Different mechanisms should produce meaningfully different reports where the evidence supports that difference. Similar mechanisms may produce similar reports. Never invent a distinction, contrast, or uniquely phrased conclusion that the chart does not support; discrimination is a check against overgeneralization, not a requirement that every report sound unique.

## 3. Structure-to-work boundary

No direct jump from a star to an occupation:

```text
天梁 != 医疗/教师
武曲 != 金融
廉贞 != 公务员
紫微 != 管理层
破军 != 创业
```

First output observable work axes: organization/market, fixed/project, rule/client, stable/route-changing, individual execution/resource management, fixed salary/performance-project/operating resources.

A broad industry family is allowed only when multiple independent evidence lines agree. It must be labeled:

```text
COARSE_CLASSIFICATION
NOT_EXACT_OCCUPATION
```

## 4. Wealth source decomposition

Every complete Wealth analysis must inspect each source separately:

```text
SELF_EARNED_INCOME
CAREER_DERIVED_WEALTH
FAMILY_OF_ORIGIN_SUPPORT
FAMILY_ASSET_BASE
SPOUSE_RESOURCE
SPOUSE_FAMILY_RESOURCE
PROPERTY_ASSET_TRANSFER
```

For each source, report `SUPPORTED / PARTIAL / UNRESOLVED / NOT_ESTABLISHED`. A present channel is not automatically the main source. Wealth is not reducible to the native Wealth palace.

## 5. Derived-palace downgrade

One derived layer is the default maximum: `ONE_DERIVED_LAYER_MAX`.

- `Spouse Career` means spouse's work/social-role structure, not actual occupation.
- `Spouse Resources` means a resource-handling/interface candidate, not income amount or ownership.
- `Spouse Parents`, `Spouse Family`, `Career Taiji`, and `Wealth Taiji` follow the same rule.
- Derived confidence is one level below an otherwise equivalent direct-palace claim.
- A second derived turn is prohibited unless a future explicit profile authorizes it.

## 6. Language boundary

Prefer observable language: organization vs customer, fixed vs project income, repeated route changes, direct family asset transfer, self-earned vs spouse/family resource, fast relation entry vs slow implementation, self-purchase vs ancestral transfer vs residence arrangement.

Do not use mystical fillers (`能量`, `人生课题`, `格局宏大`, `贵人加持`, `运势开启`) or generic phrases as substitutes for a dimension and falsifier.
