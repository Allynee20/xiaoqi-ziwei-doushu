# Question to Topic

Before selecting evidence, map the request to a Topic and, where applicable, to an explicit Project Schema dimension: Wealth A–H, Family L1–L5, or Marriage epistemic level. These schemas organize questions; they do not create traditional authority or outcomes.

先把用户问题拆为 Topic、Subquestion、对象、时间范围与所求答案类型。不要把“问了某主题”当成该领域异常。

| Topic | 常见 Subquestion |
|---|---|
| 财富 | 赚钱形成、资源处理能力、收入结构、稳定/波动、现金流速度、留存、耗散/流出、家庭支持、家庭/资产来源、事业与财富关系 |
| 事业 | 工作功能/角色、平台适配、机会/入口、能力倾向、专业认可、位置、权责、稳定/变化、事业与财富关系 |
| 婚姻/关系 | 关系模式、伴侣指涉倾向、吸引、外部注意条件、冲突机制、稳定性、情感满足、共同生活、共同财务、关系阶段 |

若问题跨 Topic，先分别分析各维度，再由 Reasoner 处理资源竞争或耦合；不得在 Primitive 层混成“整体好坏”。医疗、法律、投资等现实决定不由命盘替代。
