# Wealth Context

Canonical dimension authority: `PROJECT_SCHEMAS/WEALTH_A_H_SCHEMA.md` (`PROJECT_INVENTED_SCHEMA`). This file supplies the topic interface and must not collapse the eight dimensions.

财富不是单一“财运好坏”。主线按子问题选择：

| 子问题 | 主线接口 | 辅助接口 / 条件 | 关键分离 |
|---|---|---|---|
| 赚钱形成/收入载体 | 财帛；官禄的交付；迁移的入口 | 命身做事方式、交友对接 | 形成 != 能力 != 实际收入 |
| 资源处理能力 | 命身、财帛及直接能力证据 | 官禄责任、协作支持 | 能力不得由机会或留存倒推 |
| 收入稳定/波动 | 直接的收入节奏证据 | 官禄持续性、客户/平台 | 波动 != 速度 != 损失 |
| 现金流速度 | 财帛的周转/吞吐直接证据 | 交付、账期、回款 | 快慢 != 留不住钱 |
| 留存/沉淀 | 多接口：财帛处理、田宅固定/储存、福德消费与官禄持续性；需有资源输入锚点 | 家庭基础、明确成本机制 | 留存不属于单一宫位；留存 != 赚钱 |
| 耗散/流出 | 有方向的成本、支出、侵蚀机制 | 财帛、福德、田宅、现实合同/预算 | 耗散机制 != 低留存 != 实际损失 |
| 家庭支持 | 父母/田宅及明确支持对象 | 财帛、官禄 | 支持 != 家庭财富来源/继承 |
| 家庭/资产来源 | 直接的家庭/资产来源结构 | 田宅、父母、财帛 | V3 标为未充分建立，默认 `PARTIAL` |
| 事业与财富 | 先各自完成事业角色与财富维度 | 再综合交付、结算、留存 | 事业强不等于收入高；跨 Topic 综合由 Reasoner 负责 |

V3 已批准的两个狭窄锚点：武曲化禄在财帛宫的 direct earning formation signal；天府在田宅宫的 retention storage support signal。两者都不能扩大为财富等级、金额或结果。
